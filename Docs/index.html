How big worlds fit in small memory

Seven loading systems, from Half-Life 2's loading screens to Unreal Engine 5's World Partition. Each one answers the same two questions: what must be in memory right now, and in which order do I spend my limited bandwidth to get it there?

00

The common shape

Strip away the art and every streaming system is the same five-step loop, run every frame. The systems differ only in their answer to step 1 and in what they show during step 5.

The simulated hardware

All seven modes share one model of a storage device (SimulatedIO.cs) and one memory budget (MemoryBudget). Each mode sets numbers that suit its era, but the rules are the same:

  1. Requests wait in a priority queue. Lower number = more urgent. Strategies re-prioritise every frame.
  2. Only N requests are in flight at once (disc channels, HTTP connections, worker threads).
  3. Each request pays a fixed latency first (seek, round trip), then reads at the shared bandwidth.
  4. When the last byte arrives, the strategy decides it is resident and commits memory.
01

Discrete levels

Half-Life 2 · Source EngineDemo key 1

Don't stream at all. Exactly one map is in memory. Walking into a trigger freezes the game, throws the map away and reads the next one in a single blocking load. The trick is making the hand-over feel continuous.

How it works

  1. The world is a chain of separate maps. Only the current one is resident, so memory use is a simple step function.
  2. Neighbouring maps overlap. The overlap is built twice, once in each map, so you can't see a seam.
  3. Touching a trigger_changelevel freezes the simulation and shows "LOADING…" over the last frame.
  4. Entities inside the transition volume (trigger_transition) are saved: the player, NPC companions, that crate you pushed.
  5. The old map is unloaded, the next one is read in one blocking load, and the saved entities are re-created at landmark + offset.
Show this in the demo
  • Let autopilot reach the yellow gate. Point at the four-step checklist in the LOADING box.
  • The stats panel prints the landmark maths: the same landmark has different coordinates in each map.
  • Blue labels follow the carried entities. Crates elsewhere stay with their own map's save state.
  • Memory never holds two maps: 192 MB budget, maps are 124–158 MB each.
  • Drag bandwidth down to 5 MB/s: same design, much longer freeze.
Assets/StreamingDemo/Scripts/Modes/DiscreteLevelsMode.cs
case Phase.Playing:
    // 1) Is the player in a changelevel trigger belonging to this map?
    if (trigger.Contains(player)) StartTransition(t, t.To);   // freeze + flag entities in t.Volume
case Phase.SavingEntities: // 2) store offsets from the landmark
case Phase.Unloading:      // 3) Memory.Free(map.SizeMB)  ->  ~0 MB resident
case Phase.Loading:        // 4) one big request:  Disk.Enqueue("d1_docks.bsp", 148 MB, ...)
case Phase.Restoring:      // 5) entities re-created at landmark + offset, unfreeze

Strengths

  • Trivial memory planning: the budget is "the biggest map".
  • Each map can use the whole machine, which allows dense, hand-authored detail.
  • Easy to build, test and debug. Maps are independent.

Costs

  • The player sees every load as a freeze.
  • Back-tracking means loading the previous map again.
  • Designers must duplicate and keep in sync the geometry around every transition.

Source also writes the departing map's state into the save game, so walking back finds things the way you left them. The demo mimics this: crates that weren't carried reappear when their map loads again.

02

Cell grid

The Elder Scrolls V: Skyrim · Creation EngineDemo key 2

Cut the outdoor world into equal square cells and keep an N×N block around the player resident. Cross a cell edge and the block slides by one: a row streams in, the opposite row is dropped.

How it works

  1. The worldspace is a uniform grid. A cell bundles terrain, objects and navmesh, and is the unit of streaming.
  2. uGridsToLoad (default 5) sets the resident block. Raising it via the INI was a famous way to crash consoles.
  3. Loads are nearest-first, and the player's own cell is the most urgent of all.
  4. Pre-baked distant LOD terrain and objects cover everything outside the block.
  5. A cell buffer keeps recently dropped cells in memory, so turning back is free.
  6. If the player reaches a cell before it's resident, the game has no choice but to block: a hitch.
Show this in the demo
  • It opens on a loading screen: the whole 25-cell grid must be in before you get control.
  • Watch the green curtain slide and the yellow columns appear on every crossing.
  • Turn on wiggle over a cell edge with the cell buffer off, then on. Count the loads in the log.
  • Speed to 80+: red HITCH banners. Then try uGridsToLoad 7 and 9 and watch memory pass 400 MB.
  • Wait for a door: the exterior drops to 0 cells, then reloads behind a second loading screen.
Assets/StreamingDemo/Scripts/Modes/CellGridMode.cs · UpdateGrid()
int r = (gridsToLoad - 1) / 2;
for (dx = -r..r) for (dz = -r..r)                     // 1) desired: the N x N square
    if (cell.State == Unloaded) Disk.Enqueue(cell, priority: chebyshev(dx, dz));
    else if (cell.State == Cached) Show(cell);           //    cell-buffer hit: free
foreach (cell outside the square)                       // 3) evict
    if (cellBuffer) cell.State = Cached; else Unload(cell);
EnforceCellBuffer();                                      // 4) LRU over capacity
player.Frozen = playerCell.State != Loaded;               // 5) the hitch

Strengths

  • Predictable: memory ≈ N² × average cell size.
  • Simple to author. Artists work cell by cell.
  • Distant LOD keeps the horizon visible at almost no cost.

Costs

  • One size fits all: a dense city cell costs the same slot as an empty field.
  • Speed is capped by how fast a row of N cells loads.
  • Interiors behind loading screens break immersion.
03

Object streaming

Grand Theft Auto III → V · RenderWare / RAGEDemo key 3

Forget cells. Every model is its own streamable asset with its own streaming distance. Each frame, rank everything you're missing by urgency and push it through one slow disc in that order.

How it works

  1. Every model is listed with a streaming distance in the map data (GTA's IDE/IPL files). Large models also link to a low-detail LOD model.
  2. Each frame: urgency = distance ÷ radius. Below 1, it's wanted.
  3. Wanted-but-missing objects go into a priority queue that is re-sorted as you move.
  4. Velocity prediction also measures from where you'll be in a second or two.
  5. A fixed streaming memory pool. When it's full, the least urgent resident objects go.
  6. At high speed, detail distances shrink so the streamer can keep up (GTA V's approach).
Show this in the demo
  • Orange lines show what the disc is reading at this moment. That's the I/O budget made visible.
  • Speed to 100+: red flashes and the late pop-ins counter climbs.
  • Toggle velocity prediction off at high speed: more pop-in directly ahead.
  • Toggle lower detail at speed: the ring shrinks and pop-in drops.
  • Squeeze the memory budget to 24 MB: constant eviction churn.
Assets/StreamingDemo/Scripts/Modes/ObjectStreamingMode.cs · Tick()
focus = prediction ? pos + velocity * 1.5f : pos;
foreach (o in objects) {
    o.Urgency = min(dist(pos, o), dist(focus, o)) / (o.Radius * detail);
    if (o.Unloaded && o.Urgency < 1)      Disk.Enqueue(o, priority: o.Urgency);
    else if (o.Queued && o.Urgency > keep) Disk.Cancel(o.Request);   // free if not started
    else if (o.Queued)                    o.Request.Priority = o.Urgency;
    else if (o.Loaded && o.Urgency > keep) Unload(o);                // keep = 1.25 with hysteresis
}
EnforceBudget();   // evict highest urgency first

Strengths

  • Fine-grained: bandwidth goes to what matters most right now.
  • Dense cities are fine. Cost follows content, not area.
  • Seamless: no loading screens in the open world.

Costs

  • Many small reads: seek latency dominates on optical media.
  • Pop-in at speed is the visible failure.
  • Needs a good LOD pipeline and careful per-model distances.

On discs, where an object sits matters as much as how big it is. GTA-era games ordered their archives so that things needed together sit together, turning many seeks into one long read.

04

Rooms & doors

Metroid Prime · Jak & Daxter · God of War (2018)Demo key 4

The world is a graph of rooms. Entering a room loads its neighbours, and a door won't open until the room behind it is resident. Loading becomes part of the level design.

How it works

  1. Rooms are nodes, doors are edges. Rooms are the unit of streaming.
  2. Desired set: a breadth-first search through doors, out to the prefetch depth (normally 1).
  3. The room behind the door you're walking towards gets the highest priority.
  4. A door is locked while either side isn't resident. A slow disc shows up as a slow door, never a loading screen.
  5. Rooms more than one door away are released when you enter a new room.
Show this in the demo
  • The overview is the room graph. Red squares are locked doors, blue are open.
  • At 2.5 MB/s the player waits at the Crystal Hall door. "Door waits" counts it.
  • Prefetch depth 2: no waits, but memory goes red past 24 MB.
  • Bandwidth 10 MB/s: doors are always open. The design hides the disc completely.
Assets/StreamingDemo/Scripts/Modes/RoomPortalMode.cs · Tick()
desired = BreadthFirst(current, depth: prefetchDepth);        // 2) neighbours
foreach (room in desired)
    if (room.Unloaded) Disk.Enqueue(room, priority: DistanceTo(room));
foreach (room not in desired) Unload(room);                 // 4) release

bool Locked(door) => door.A.State != Loaded || door.B.State != Loaded;
bool IsWalkable(p) => !lockedDoors.Any(d => d.Contains(p)) && rooms.Any(r => r.Contains(p));

Strengths

  • No loading screens, and the peak memory is bounded by design.
  • Each room can be dense because it only shares memory with a few neighbours.
  • Waiting is disguised: elevators, crawl spaces, squeezing through cracks, boat rides.

Costs

  • The layout serves the streamer: corridors and airlocks everywhere.
  • Open, wide vistas are hard.
  • Fast movement shows up as doors that are slow to open.

The GameCube had 24 MB of main memory plus 16 MB of slower auxiliary RAM. Jak & Daxter used the same idea at a larger scale, keeping two level-sized buffers and swapping one while you travel through a connecting area.

05

Chunks: generate or load

Minecraft · No Man's SkyDemo key 5

An endless grid of 16×16 chunks. Ground you've never seen is generated from the world seed on worker threads. Ground you've visited is read back from region files. Two sources, one nearest-first queue.

How it works

  1. Desired set: every chunk within the render distance (a circle) of the player's chunk.
  2. Saved? Queue a cheap region-file read. Never seen? Queue an expensive generation job.
  3. Both queues are nearest-first and re-sorted when the player crosses into a new chunk.
  4. Chunks beyond render distance + 2 are unloaded. The extra ring is hysteresis.
  5. Fog sits just inside the render distance, so the world's edge fades instead of ending.
Show this in the demo
  • First lap: purple squares = worldgen workers busy. Second lap: blue flashes = region files. Compare the counters.
  • Speed 40+ with 2 workers: the player hits the void and freezes.
  • Raise worker threads to 6 at the same speed.
  • Turn fog off to show the hard edge it was hiding.
  • Delete save: the next lap regenerates the identical terrain.
Assets/StreamingDemo/Scripts/Modes/ChunkGenerationMode.cs · Tick()
for (dx, dz within renderDistance circle) {
    if (chunk.Unloaded)
        if (saved.Contains(c)) Disk.Enqueue("r.x.z.mca", 0.06 MB, priority: d2);   // load
        else                   gen.Enqueue("gen(x,z)", 1 chunk, priority: d2);    // generate
}
void OnChunkReady(chunk, generated) {
    if (generated && saving) saved.Add(chunk.C);                                 // write region file
    chunk.Mesh = BuildChunk(chunk.C);   // deterministic from the seed
}

Strengths

  • Effectively infinite worlds with no authoring cost per square metre.
  • Disk holds only what was visited (or, like No Man's Sky, only what changed).
  • Uniform chunks make threading and meshing simple.

Costs

  • Generation competes for CPU with the game itself.
  • Fast travel outruns the workers.
  • Uniform chunks spend the same effort on empty sky as on a city.
06

Quadtree LOD

Microsoft Flight Simulator · Google Earth · CesiumDemo key 6

A planet can't be a grid: the view goes from orbit to runway. Terrain becomes a tree of tiles. Every child covers a quarter of its parent at the same vertex count, and tiles split as the camera gets close.

How it works

  1. The root tile covers the whole world at low resolution. Each level doubles the detail.
  2. Every frame, walk down from the root. Split a tile when the viewer is close relative to its size.
  3. Shallow tiles have the highest priority, so there's always something on screen.
  4. Only descend into a tile's children when all four are resident. Until then, draw the parent.
  5. Tiles that no selection has touched for a few seconds are evicted, children before parents.
Show this in the demo
  • The flight dives to 40 u and climbs to 2,200 u. Watch the depth colours (red, yellow, green, blue) chase the aircraft.
  • The overview is the live quadtree. Yellow squares are tile requests.
  • Drop bandwidth to 1 MB/s: the view stays covered, just blurrier. That's coarse-first at work.
  • Toggle Freeze LOD, then zoom out with the wheel to see the structure the viewer produced.
Assets/StreamingDemo/Scripts/Modes/QuadtreeLodMode.cs · Select()
void Select(Node n) {
    if (n.Depth < maxDepth && Distance(viewer, n) < n.Size * splitFactor) {
        EnsureChildren(n);
        bool allReady = true;
        foreach (c in n.Children)
            if (c.State != Loaded) { allReady = false; Request(c); }   // priority: depth first
        if (allReady) { foreach (c in n.Children) Select(c); return; }
    }
    render.Add(n);   // never a hole: the parent covers its children's area
}

Strengths

  • Handles scale across many orders of magnitude.
  • Degrades gracefully: a slow network means blurrier, not missing.
  • The same structure works for imagery, heights, buildings and point clouds.

Costs

  • Cracks and popping between levels need skirts, morphing or blending.
  • Lots of small requests: latency matters more than raw bandwidth.
  • Works best for heightfield terrain. Interiors and caves need something else.
07

World Partition

Unreal Engine 5 · Fortnite, The Matrix AwakensDemo key 7

The modern engine-level answer combines the earlier ideas. One world is sliced automatically into several grids by object size. Merged HLOD proxies stand in beyond range, data layers switch whole sets of actors, and any number of streaming sources drive it.

How it works

  1. Build one big world. At cook time every actor is assigned to a cell of a runtime grid.
  2. Several grids, each with its own cell size and loading range: landmarks from far away, foliage only close up.
  3. Streaming sources (the player, a cinematic camera, a teleport target) each project loading ranges.
  4. Wanted = intersects any source's range. Priority: bigger grids first, then distance.
  5. HLOD proxies replace unloaded cells. Data layers add or remove sets of cells at runtime.
Show this in the demo
  • Three coloured rings = three grids' ranges. The overview shows nested cells.
  • Toggle HLOD off: the distance turns empty. On: green canopy blocks and roof blocks.
  • Turn on the Festival data layer: tents and lanterns stream into village cells.
  • Teleport with pre-warm off: "missing cells on arrival". With it on: a yellow beacon loads the far side first, then a clean jump.
Assets/StreamingDemo/Scripts/Modes/WorldPartitionMode.cs · Tick()
sources = [player] + (warming ? [teleportTarget] : []);
foreach (cell in cells) {
    if (cell.DataLayer && !layerActive) { Release(cell); continue; }
    float d = sources.Min(s => DistanceToRect(s, cell.Rect));
    bool wanted = d <= cell.Grid.Range;
    if (wanted && cell.Unloaded) Disk.Enqueue(cell, priority: cell.Grid.Index * 0.25f + d / range);
    if (!wanted) Release(cell);                // HLOD proxy becomes visible again
}
if (warming && DestinationReady(target)) Teleport(target);

Strengths

  • Automatic: no hand-placed streaming volumes or level splits.
  • Grids per object size fix the "one size fits all" problem of a single grid.
  • Streaming sources make teleports, cutscenes and split-screen first-class.

Costs

  • HLOD generation is a heavy offline build step.
  • Many tuning knobs per grid and per layer.
  • Still bound by disk speed: a sprint across the map needs a fast SSD.

Fast SSDs change the limits again. Ratchet & Clank: Rift Apart swaps whole planets through its rift portals in seconds, because the console can fill a large part of memory almost instantly.

Side by side

Each step fixes a limitation of the previous one. In practice, shipped games mix them: World of Warcraft streams each continent seamlessly but uses loading screens for dungeons and continent changes.

Questions to take back to our own projects

  1. What is our unit of streaming, and does its cost follow content or area?
  2. What does the player see while data is missing? Choose it on purpose: LOD, fog, a door, a loading screen.
  3. How is priority computed, and is it re-evaluated as the player moves?
  4. Do we have hysteresis, so standing on a boundary doesn't thrash the disk?
  5. What is the worst case: top speed, cold teleport, smallest memory platform?

Where the code lives

  1. Scripts/Core/SimulatedIO.cs: the disk model and memory budget every mode shares.
  2. Scripts/Core/DemoMode.cs: the base class and the five-step contract.
  3. Scripts/Modes/*.cs: one file per system. Search for CORE ALGORITHM.
  4. Scripts/Rendering: mesh builder, materials, tweens. Scripts/UI: the HUD.
  5. Resources/Shaders: vertex-colour lit, hologram glow and grid floor shaders (URP).
Presenter tips
  • Each system resets the same simulated hardware, so you can compare numbers fairly.
  • The two sliders that tell the story everywhere are movement speed and bandwidth.
  • Toggle fog in any mode: it has hidden the edge of the loaded world for decades.
  • The log on the bottom right narrates every load, eviction and hitch as it happens.
